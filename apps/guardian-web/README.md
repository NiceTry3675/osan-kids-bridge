# 보호자 모바일 웹

검수된 자녀 프로그램을 둘러보고, 자녀 조건과 가능한 시간으로 검색한 뒤 기관의 신청처를 확인하는 프론트엔드입니다. 로그인과 앱 내 신청은 없습니다.

## 로컬 실행

```bash
npm ci
npm run dev
```

표시된 로컬 주소를 브라우저에서 엽니다. `npm run build`로 타입 검사와 배포용 빌드를, `npm test`로 입력 직렬화와 가상 검색 판정을 확인합니다.

로컬 개발은 `.env.development`의 `VITE_DATA_MODE=demo`로 화면 점검용 가상 공고를 표시합니다. 가상 공고에는 실제 신청 정보가 없으며 화면 상단에도 이를 알립니다. 일반 배포 빌드는 API 주소가 없을 때 가상 공고로 자동 대체하지 않습니다.

## 언어와 검색 상태

목표 화면 언어는 쉬운 한국어, 베트남어, 중국어입니다. 선택한 언어는 이 브라우저에 저장되며 검색 조건과 별개로 바뀝니다. 현재 베트남어·중국어 문구는 검수 전 초안이므로 명시적 시연 모드에서만 선택할 수 있고, 공개 빌드는 쉬운 한국어만 제공합니다. 공고에서 받은 제목·대상·설명·기관명은 원문을 그대로 보여 줍니다. 번역 검수가 완료된 공고 문구를 제공하는 데이터 계약이 아직 없으므로 한국어 외 시연 화면에는 원문 표시 안내가 함께 나옵니다. 게시 기준과 검수 기록은 [CONTENT_REVIEW.md](./CONTENT_REVIEW.md)에 적었습니다.

검색 조건은 현재 브라우저 탭의 세션 저장소에만 보관합니다. 결과에서 상세로 이동하거나 새로고침한 뒤에도 조건을 되살리되, 직접 받은 상세 공유 주소에는 저장된 자녀 조건을 적용하지 않습니다. 처음으로 돌아가면 조건을 지웁니다. 공유 주소에는 검색 조건을 넣지 않습니다.

상세 화면은 신청 상태와 참여 자격을 별도로 표시합니다. 기관의 상담·수업 언어, 신청 페이지 언어, 동반 가능 여부와 필요한 한국어 수준은 확인된 데이터가 없으면 지원된다고 표현하지 않고 기관에 확인할 항목으로 표시합니다. 시연 공고에는 자료 확인일·원문 링크를 표시하지 않으며 가상 신청 링크와 전화번호는 실제로 연결하지 않습니다.

## API 연결

환경 변수 `VITE_API_BASE_URL`을 설정하면 다음 요청을 사용합니다.

로컬 개발에서 실제 API를 시험할 때는 `.env.development`의 시연 설정을 덮어써 `VITE_DATA_MODE=api VITE_API_BASE_URL=https://API주소 npm run dev`로 실행합니다.

- `POST /programs/search`: 빈 조건 `{}` 허용. `results`와 `needs_confirmation`을 반환합니다.
- `GET /programs/{id}`: 공유 주소에서 개별 공고를 조회합니다. `404`와 `410`은 조회 불가 화면으로, 다른 요청 오류는 재시도 화면으로 처리합니다.
- `POST /programs/{id}/evaluate`: 자녀·시간 조건을 적용해 목록에서 상세로 들어갈 때 같은 조건으로 상세 판정을 요청합니다. 직접 공유 링크 진입은 조건 없는 `GET`을 사용합니다.

제안된 필드 형식은 `src/types.ts`에 있습니다. 실제 API 경로·응답 필드·CORS 정책, 특히 조건 적용 상세 경로는 백엔드 계약이 정해지면 맞춰야 합니다. 배포 서버는 `/programs/{id}` 새로고침을 `index.html`로 돌리는 SPA 경로 처리가 필요합니다. 배포용 가상 공고 시연이 필요하면 `VITE_DATA_MODE=demo npm run build`처럼 명시적으로 빌드합니다.

현재 버전은 보호자 흐름을 검증하는 프론트엔드 초안입니다. 시간 및 자격 판정은 실제 API를 쓸 때 서버 응답을 표시하며, `src/mockPrograms.ts`의 판정은 가상 공고 시연에만 사용합니다.
