# 보호자 모바일 웹

검수된 자녀 프로그램을 둘러보고, 자녀 조건과 가능한 시간으로 좁힌 뒤 기관의 신청·문의처를 확인하는 화면입니다. 로그인과 앱 안 신청은 없습니다. 기준 문서는 `program_connection_spec_v2_2.md`입니다.

## 실행

저장소 맨 위에서 `npm install` 후 `npm run dev:guardian`. 이 폴더에서 `npm run dev`, `npm test`, `npm run build`도 됩니다.

로컬 개발은 `.env.development`의 `VITE_DATA_MODE=demo`로 가상 공고를 씁니다. 일반 배포 빌드는 API 주소가 없으면 가상 공고로 대신하지 않고 “공고 서버가 아직 연결되지 않았어요”를 보여 줍니다. 시연용 배포가 필요하면 `VITE_DATA_MODE=demo npm run build`처럼 명시합니다. 서버에 SPA 경로 설정을 할 수 없는 정적 호스팅에서는 `VITE_ROUTER=hash`를 함께 주면 상세 주소가 `#/programs/{id}`가 됩니다. 시연 공고의 신청 링크·전화번호는 실제로 연결하지 않습니다.

## 화면 (유저플로우 v5, 7화면)

페이지는 홈(`/`)과 상세(`/programs/{id}`) 두 개뿐이고, 나머지는 그 위에 열고 닫는 시트입니다. 그림은 `docs/userflow/guardian.html`.

| 번호 | 화면 | 종류 | 하는 일 |
|---|---|---|---|
| 01 | 첫 화면·언어 고르기 | 처음 1회 | 기본 주소로 처음 왔을 때만. 공유 링크로 오면 건너뜀 |
| 02 | 홈 | 페이지 `/` | 제목 → ‘내 언어로 바꾼 포스터’ 띠 → ‘우리 아이에게 맞게 보기’ → AI 상담 → 분야 타일, 아래에 조건 없이 모든 공고 |
| 03 | 조건 넣기 | 시트 | 아이·시간·먼저 보기·무료를 한 화면에서 |
| 04 | 결과 | 홈과 같은 페이지 | 조건 칩 · 결과 / 시간 확인 필요 · 결과 없음 |
| 05 | 상세 | 페이지 | 머리글(제목 옆 내 언어 포스터 썸네일) → 조건을 넣고 왔으면 ‘맞아요’ 비교 → 핵심 사실 → ‘기관이 확인해 덧붙인 안내’ 카드 → 확인할 점 → AI 상담 → (조건 없이 왔으면 비교 안내) → 포스터 → 소개·회차·동반·언어, 하단에 ‘물어보기·신청하러 가기’ |
| 06 | 신청·물어보기 | 시트 | 탭 두 개. 외부 이동 전 안내, 원문 → 확인된 문의처 |
| 07 | 내 언어 안내가 없을 때 | 상세의 상태 | 없음을 먼저 알리고 원문은 접어 둠 |

- 목록과 상세는 대상 → 일정 → 장소 → 비용 → 신청 순서를 똑같이 씁니다.
- 목록이나 AI 상담이 권한 공고에서 들어간 상세는 지금 넣은 조건으로 다시 판정(`POST /programs/{id}/evaluate`)하고, 공유 링크로 바로 연 상세는 조건 없이 조회(`GET`)하며 “공유 링크로 열어서 비교하지 않았어요”라고 알립니다. 조건 없이 들어오면 “조건을 넣지 않아 비교하지 않았어요”라고 합니다.
- 기관이 덧붙인 안내(`addenda`)는 상세의 초록 카드로 보입니다. 서버가 베트남어·중국어로 옮긴 문장(`translations`)이 있으면 그것을 ‘AI 번역’ 표시와 함께, 기관이 쓴 한국어 원문을 그 아래에 둡니다. 안내가 답한 주제(`covers`)는 ‘기관에 확인할 점’과 목록의 확인할 점 개수에서 빠지고, 비용(`cost`)에 답했으면 목록·상세의 비용 칸이 ‘비용 확인 필요’ 대신 그 안내를 보여 줍니다.
- 뒤로 가기로 목록에 돌아오면 보던 위치로 돌아갑니다. 조건은 이 탭의 세션 저장소에만 두고, 공유 주소에는 넣지 않습니다.
- 신청과 문의는 다른 행동입니다. 문의처는 확인된 것만 보여 주고, 없으면 “확인된 문의처가 없어요”라고 말합니다. 운영 시간·상담 언어도 확인된 경우에만 씁니다.
- 자료 확인일을 늘 보여 주고, 원문이 바뀌어 재검수 중인 공고는 맨 위에 알립니다.

## AI 상담 도우미와 번역 포스터

API에 연결한 화면(`VITE_DATA_MODE=api`)에서만 보입니다. 시연 어댑터(mock)로는 대신하지 않습니다.

- **AI에게 물어보기**(홈·상세·물어보기 시트): program-api의 상담 에이전트(`POST /agent/chat`)가 검수된 공고만으로 화면 언어로 답합니다. 답마다 확인한 과정(공고 읽기·조건 비교·문의문 작성 등), 원문 근거 인용, 기관에 보낼 한국어 문의문(복사·전화), 공고에 답이 없던 질문을 보여 줍니다. '기관에 이름 없이 알리기'를 눌러야만 질문이 기관 대시보드로 갑니다(`src/screens/chat`).
- **번역 포스터**(홈 띠·목록·상세): 화면 언어의 번역 포스터가 있으면 보여 주고 무엇을 원본과 대조했는지 적습니다. 담당자 승인 전이면 형광펜으로 알리고, 한국어 원본으로 바꿔 볼 수 있습니다(`src/screens/detail/PosterSection.tsx`).
  - 홈 띠·목록·상세 머리글은 정사각형 썸네일(`GET /posters/{id}/{variant}?w=`, 그려지는 폭의 두 배를 128·256·384·512 중에서)을 받고, 원래 크기 이미지는 상세의 포스터 구역(크게 보기)에서만 받습니다.
  - 번역본 이미지를 못 불러오면 한국어 원본으로, 원본도 안 되면 분야 그림(목록)·포스터 그림(홈 띠)으로 바꾸고, 상세의 포스터 구역은 감춥니다(`src/lib/poster.ts`).

## 언어

- 화면 언어: 쉬운 한국어(검수됨), 베트남어·중국어(초안). 공개 빌드에서는 초안 언어가 ‘번역 검수 중’으로만 보이고 고를 수 없습니다. 정책은 `src/i18n/policy.ts`의 `UI_REVIEW` 한 곳에서 바꿉니다.
- 공고 글: `summaries_by_language`에 그 언어의 검수본이 있으면 그 글을 쓰고 “원문과 대조한 안내예요”를 표시합니다. 없으면 상세 맨 위에 “이 공고의 ○○ 안내는 아직 없어요”와 대신 확인할 경로(확인된 상담 언어가 있는지)를 먼저 알리고, 한국어 원문은 ‘한국어 원문’ 표시와 함께 접어 둡니다.
- 화면 언어, 기관 상담·수업 언어, 신청 페이지 언어를 따로 보여 주고, 미상은 “확인되지 않았어요”로 둡니다.
- 문구는 `src/i18n/messages.ts`. 세 언어의 키·변수가 같은지는 테스트가 확인하지만 뜻과 자연스러움은 사람이 검수해야 합니다(`CONTENT_REVIEW.md`).

## 구조

```
src/
  App.tsx            페이지 전환(홈·상세), 첫 화면, 언어 고르기
  data/              types.ts(명세 6장 계약) · api.ts(서버/데모 경계) · agent.ts(AI 상담·포스터 서버 경계) · mock.ts(데모 어댑터·판정 재현)
  i18n/              messages.ts(3개 언어 문구) · policy.ts(공개 언어 정책) · index.tsx(Provider·translate)
  lib/
    filters.ts       조건 선택지·입력 검사·조건 칩
    format.ts        날짜·회차·장소·비용·신청 상태·언어 이름 표기
    content.ts       공고 글의 언어 선택, 기관에 확인할 점, 기관 추가 안내(비용·번역), 신청 가능 여부
    poster.ts        포스터 이미지 고르기(번역본 → 원본 → 없음)
    router.ts        주소(/, /programs/{id})와 목록 스크롤 복원
    session.ts       조건을 탭 세션에만 보관·검사해 되살리기
  components/        Icon · feedback(상태·형광펜·알림·빈 화면) · Sheet(공통 시트) · links(외부·전화) · korean(문장 속 한국어에만 lang) · ProgramItem
  screens/
    intro/           01 첫 화면 · art(첫 화면·홈이 함께 쓰는 그림과 아이콘)
    home/            02 홈·04 결과(HomeScreen) · PosterStrip(내 언어로 바꾼 포스터) · 03 조건 시트 · useSearch
    detail/          05 상세 · sections(상세의 각 부분) · PosterSection(포스터·머리글 썸네일) · usePosterInfo · 06 신청·물어보기 시트 · useProgram
    chat/            AI 상담 도우미 시트(ChatSheet) · AiEntry(홈·상세의 여는 카드)
  styles/            base · intro · home · detail · sheet · chat
  test/              판정·API 경계·언어 정책·목록 카드·상세·상담·화면 이동(jsdom)
```

화면 하나가 유저플로우 번호 하나와 맞도록 나눴습니다. 표기는 `lib/format`, 공고 내용 판단은 `lib/content`, 서버와의 경계는 `data/api` 한 곳에만 둡니다.

판정 로직은 서버(준현 담당)의 몫이고, `mock.ts`는 화면 동작을 시험하려고 명세 4·5장을 재현한 것입니다. 서버 계약이 바뀌면 `data/types.ts`와 명세 6장을 함께 고칩니다.
