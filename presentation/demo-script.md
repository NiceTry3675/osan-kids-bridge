# 2분 시연영상 콘티와 내레이션 대본

시연영상이다. 장면마다 **부모님이나 기관 담당자가 실제 화면에서 하는 일**을 따라가고, 에이전트는 그 행동의 결과로 나온다. 문제 정의(왜 필요한가)는 발표자료가 맡는다.

중심 메시지: **부모님이 몰랐던 것과 묻지 못했던 것이 기관에 닿아, 공고와 다음 프로그램이 바뀐다.** 그래서 영상은 번역이 아니라 두 방향 순환으로 시작한다(부모님 휴대폰 → '못 찾은 질문' → 기관, 기관 → '덧붙인 안내' → 부모님 휴대폰). 포스터 통번역은 입구다(읽을 수 있어야 물을 수 있다). 부모님이 포스터를 본 뒤에 짧은 '뒷이야기'로만 나온다. 한 줄 소개는 어디서나 **'부모님의 질문이 다음 프로그램이 되는 곳'**.

- 화면: 부모님 휴대폰(보호자 웹, 375×812)·기관 관리자 화면(데스크톱)·포스터 무대를 한 장의 큰 캔버스에 놓고, 카메라가 지금 일이 일어나는 곳으로 확대·이동한다. 누르는 곳에는 커서와 물결 표시. 포스터 무대와 휴대폰·기관 화면 사이처럼 빈 캔버스를 오래 지나가야 하는 곳(휴대폰 → 뒷이야기, 포스터 → 검수 화면, 검수 화면 → 상담, 편성 → 마무리)은 카메라를 옮기지 않고 0.3초 동안 겹쳐 바꾼다. 휴대폰 ↔ 기관 화면의 넓게 보기(두 화살표)는 순환을 보여 주는 장면이라 카메라가 부드러운 곡선으로 움직이고, 화살표는 카메라가 다음 화면에 닿은 뒤에 꺼진다
- 낱말: 나라·국적은 말하지 않고(사람 이름도 쓰지 않는다), 사람은 '부모님', 가구·통계는 '가정'이라고 한다. 언어 이름은 화면이 필요할 때만 말한다(Tiếng Việt를 누를 때 '베트남어로 해 볼게요', 중국어 화면 장면의 '중국어가 편한 다른 가정'). 언어는 그 가정이 편한 말이지 나라가 아니다. 화면 캡처 속 앱 글자(예: 기관 화면의 '보호자 질문' 탭, 상담이 쓴 문의문)는 앱 그대로 둔다
- 언어: 제품이 실제로 내는 **쉬운 한국어 · Tiếng Việt · 中文**만 보인다. 내레이션은 '언어는 아직 세 개예요'로 세 언어만 있다고 말한다. 첫 가정은 베트남어 화면, 다시 묻는 다른 가정은 중국어 화면이고, 포스터 장면은 베트남어와 중국어 번역을 같은 크기로 나란히 놓고 날짜 줄을 확대할 때도 두 언어의 날짜 줄을 한 화면에 함께 둔다. 그 밖의 언어는 영상에 나오지 않는다(앱의 언어 찾기에서는 '아직 제공하지 않음'으로만 뜬다)
- 소리: 내레이션은 `gemini-3.8-flash-tts`(목소리 Kore)로 장면마다 만들어 장면 시작에 얹는다(`build/narrate.mts`). 그래서 화면 글자는 최소로: 표지의 서비스 이름과 한 줄 소개, 장면 표시('누가 · 무엇'. 카메라가 새 장면으로 움직이기 시작하면 앞 장면의 장면 표시와 구석 표시를 바로 내리고, 카메라가 거의 도착했을 때 왼쪽 위 빈 곳에 크게 약 2초(공고 보완·다시 묻기는 0.9초: 확대하는 동안 작아지게), 그 뒤 왼쪽 아래에 작게), 부모님 질문의 한국어 번역 말풍선, 상담 에이전트가 한 일의 한국어 풀이(두 말풍선은 낱말 중간에서 줄을 바꾸지 않고, 너비와 큰 장면 표시 크기를 휴대폰 베젤 왼쪽 빈 곳에 맞춘다), 강조 테두리의 짧은 한국어 이름표, 오른쪽 아래 구석의 '줄인 것' 표시
- 작은 장면 표시와 구석 표시는 아래 띠에 함께 있다. 휴대폰 장면은 휴대폰 양옆 빈 곳, 기관 화면과 포스터 확대는 카메라가 아래 띠를 비워 두고 바탕과 같은 크림색으로 완전히 덮어(반투명이 아니라 띠 아래 글자가 비치지 않는다) 앱 글자 위에 얹히지 않는다. 테두리 이름표도 앱 글자를 덮지 않게 휴대폰 옆 빈 캔버스나 빈 여백에 둔다(휴대폰 옆이 좁으면 두 줄). 기관 화면은 왼쪽 열(공고 목록·통계)을 통째로 넣거나 통째로 빼서 반쯤 잘린 제목이 없다
- 색: 크림 바탕·코랄·초록 (발표자료와 같은 톤)

> 자동 녹화: `presentation/build/record-demo.js`가 아래 콘티대로 약 1분 40초(99.8초, 장면 8개)짜리 영상을 만든다.
> - `node record-demo.js` → `presentation/osan-kids-bridge-demo.mp4` (제출용)
> - `PROMPTER=1 node record-demo.js` → `presentation/osan-kids-bridge-demo-prompter.mp4` (녹음용: 화면 아래에 그 장면의 대본이 뜬다)
>
> 장면 길이는 대본을 **초당 4.6음절**(학생이 또박또박 읽는 속도)에 **쉼표·마침표마다 0.3초**(실제로 읽는 사람이 쉬는 시간)를 더해 읽는 시간 + 0.6초보다 짧아지지 않는다(대본은 스크립트의 `SCENES`, 지금 대본만 약 98.7초). 화면의 중요한 순간(화살표 둘, 세 언어, Tiếng Việt 누르기, 맞는 공고, 두 언어 1회차와 검증, 날짜 줄, 담당자 승인 줄, '기관에 물어볼 것' 줄, 한국어 문의문, 기관에 알리기, 빈칸과 코드 검사 줄, 덧붙이기, 답함 표시, 중국어 답과 근거, 편성안 두 반, 토요일 오전과 견준 줄, 마무리 마디)은 그 말을 읽기 시작하는 시각(스크립트의 `cue()`: 같은 속도로 장면 시작부터 셈)에 맞춰 두었고, 녹화가 끝나면 장면마다 그 시각을 `build/render/video/timings.json`의 `marks`에 남긴다. 장면 합계나 실제 영상이 118초를 넘으면 스크립트가 인코딩 전에 멈춘다.
> 녹화 전에 상담 답 2개(베트남어, 중국어)와 공고 보완 초안을 실제 API로 받아 `build/render/prefetch.json`에 저장해 두고(두 번째 중국어 답은 영상과 같은 추가 안내를 잠시 저장해 받은 뒤 지움), 편성안은 `capture.js plan`이 받아 둔 `build/render/plan-result.json`(발표자료 캡처와 같은 결과)을 쓴다. 녹화 중에는 0.9~1.3초 만에 돌려준다. 새로 받으려면 `FRESH=1 node record-demo.js`(Gemini 호출). 중국어 답의 첫 문장이 '참가비 무료'와 '운동화'를 말하고 추가 안내를 인용할 때까지 세 번까지 다시 묻고, 그래도 안 되거나 다른 검사를 통과하지 못하면 멈추므로 다시 실행한다(실패해도 추가 안내는 지운다). 예전 베트남어판 `prefetch.json`이 남아 있으면 `FRESH=1`을 하라며 멈춘다.
> 베트남어 포스터 승인은 녹화를 시작하기 전에 실제 API로 한다(부모님 장면이 포스터 장면보다 앞이라, 부모님이 보는 '담당자 확인' 줄이 녹화 안에서 사실이게). 스크립트가 승인 전 포스터 기록을 `build/render/poster-report-before-approval.json`에 보관하고, 녹화가 끝나면(실패해도) 되돌린다. 녹화 뒤에는 추가 안내·부모님 질문도 지워 다음 녹화가 처음 상태(포스터 '담당자 확인 전', 추가 안내 없음, 질문 없음)에서 시작한다.

## 준비 (녹화 전)

```bash
# 1) API (시연 데이터, 기준 시각 2026-10-15 10:00 고정)
npm run demo -w @osan-kids-bridge/program-api
# 2) 보호자 웹 (API에 연결)
VITE_DATA_MODE=api VITE_API_BASE_URL=http://127.0.0.1:8787 npm run dev -w @osan-kids-bridge/guardian-web
# 3) 기관 대시보드 (보호자 질문 탭이 API를 읽음)
VITE_API_BASE_URL=http://127.0.0.1:8787 npm run dev -w @osan-kids-bridge/institution-dashboard -- --port 5174
```

- `.claude/launch.json`에 같은 설정이 있다(program-api-demo, guardian-web-api, institution-dashboard).
- 번역 포스터와 회차별 이미지는 `apps/program-api/data/local/translated/`에 있어야 한다(없으면 `npm run poster -w @osan-kids-bridge/program-api`, 운동회 베트남어는 `--demo-fault`로 오류 주입판, 운동회 중국어는 오류 주입 없이). 운동회 중국어 기록에 자동 검증을 통과한 회차가 없으면 스크립트가 멈춘다.
- 보호자 웹은 처음 온 사람처럼(첫 화면, 쉬운 한국어) 시작한다. 다시 묻기 장면 직전에 보호자 웹이 기억하는 화면 언어를 중국어로 바꾸고 새로 연다. 녹화용 브라우저는 매번 새 프로필이라 따로 지울 것이 없다.

## 정직하게 밝히는 것

화면 오른쪽 아래 구석(소리 없이 보는 심사위원용, 앱 글자를 덮지 않게 기관 화면·포스터 확대는 아래 띠를 비워 크림색으로 덮고 그 위에 둔다)과 이 문서에 밝힌다:

- 표지: 화살표 두 개는 실제로 저장된 데이터의 흐름이다(부모님이 '기관에 알리기'로 보낸 이름 없는 질문, 담당자가 확정한 추가 안내). **에이전트끼리 서로 부르지 않는다.** 저장된 질문·안내를 다음 에이전트가 읽어서 이어진다. 부모님이 넣은 조건이 통계로 쌓이는 화살표('익명 통계')는 넣지 않았다(**조건은 실시간으로 모으지 않는다**).
- 언어: 보이는 언어는 제품이 실제로 내는 쉬운 한국어·베트남어·중국어뿐이다(화면·포스터·상담 모두). 첫 화면의 'Tiếng Việt · 中文' 옆 '번역 초안' 표시는 앱이 붙이는 것(검수 전 화면 문구)이라 그대로 둔다. 다른 언어는 같은 방식으로 늘릴 수 있지만 영상에서는 보이거나 말하지 않는다.

'준비물은 안 나와 있대요'는 답의 'Cần hỏi cơ quan'(기관에 물어볼 것) 줄이 실제로 '준비물은 공고에 없다'고 말하는 것을 테두리로 보여 준다. **제품의 코드 검사는 상담 답의 근거 인용만 확인하고, 답 문장 자체는 검사하지 않는다.** 영상에서 답 문장에 붙인 이름표가 틀리지 않게 확인하는 것은 녹화 스크립트의 일이다(아래 다시 묻기).
- 공고 보완 장면: '시연용 예시 질문 포함'(질문 목록 중 방금 알린 한 개만 실제, 나머지는 대시보드의 시연용 예시), '응답 대기 줄임 (실제 10~20초)', '빈칸에 넣는 값은 시연용'(무료, 운동하기 편한 옷과 운동화). '지어내면 코드가 막아요'는 보완 초안의 코드 검사(빈칸 밖에 공고에 없는 숫자·날짜·수량이나 답을 단정하는 말이 있으면 통과하지 못함)를 말한다.
- 다시 묻기: '응답 대기 줄임'. 두 번째(중국어) 답은 녹화 전에 같은 추가 안내를 잠시 저장해 실제 API로 받은 것이다. 이름표 '중국어 답: 참가비 무료 / 운동하기 편한 옷과 운동화'는 그 답 첫 문장의 한국어 뜻이고, 스크립트가 그 첫 문장에 '免费'와 '鞋'가 있는지 확인한 뒤에만 녹화한다. 상세는 초록 추가 안내 카드부터 찍는다: 그 위 공고 요약의 참가비 줄은 여전히 '기관에 확인'이라, '참가비: 무료' 안내와 함께 보이면 서로 어긋나 보인다(앱은 추가 안내가 어느 항목의 답인지 모른다. 알려진 한계). 추가 안내 문장은 기관이 쓴 한국어 그대로이고, 카드 제목과 설명만 중국어다(구석 표시로도 밝힌다).
- 편성 장면: '통계는 시연용 가상 응답 400가정', '응답 대기 줄임 (실제 20~30초)'. **통계는 가상 응답 400가정**이고(내레이션 첫 말도 '통계는 가상 응답이에요'), **장소는 가상이며 앱이 '가상 장소'로 표시한다.** '거의 두 배'는 편성안 카드의 '지금처럼 모두 토요일 오전 22% > 이 편성안 41%'(시간과 동네까지 맞는 가정 비율, 코드가 계산)를 말한다.
- 녹화에서만 하는 화면 조정(앱 코드는 그대로): 상담 답을 기다리는 동안 시트가 대화 끝으로 자동 스크롤하지 않게 하고 '한 일' 카드로 바로 옮긴다(답 끝이 먼저 비쳤다 돌아오지 않게). 공고 보완 화면은 페이지 끝에 빈 곳을 더해 확정 버튼을 카메라 창 안으로 올린다. 시트를 열 때 생기는 키보드 포커스 테두리는 숨긴다. 상담 질문을 보낼 때는 보내기 직전 화면(마지막 화면 기록 프레임)을 잠시 덮어 두고, 보낸 질문과 '확인 중'이 그려지면 카메라를 그 자리로 옮긴 뒤 걷어 낸다(입력칸이 비고 대화가 잠시 빈 채로 보이는 순간을 찍지 않게). 기관 검수 화면의 번역 포스터 칸은 녹화 전에 아래 끝(승인 줄·검증 기록)까지 내려 둔다.

## 내레이션 넣기

- `cd apps/program-api && npx tsx ../../presentation/build/narrate.mts`: `SCENES` 대본을 장면별로 `gemini-3.8-flash-tts`로 읽히고, 앞뒤 무음을 잘라 `render/video/timings.json`의 장면 시작(남는 시간의 절반, 최대 0.6초 뒤)에 얹은 뒤 -16 LUFS로 맞춰 합친다. 소리 없는 원본은 `osan-kids-bridge-demo-silent.mp4`로 남는다
- 대본이 바뀐 장면만 다시 만든다(`render/narration/<장면>.json`). 지시문을 대본에 붙이면 TTS가 지시문까지 읽고, 시스템 지시는 받지 않으므로 대본만 보낸다. 만든 음성은 Gemini 받아쓰기로 대본과 대조했다
- 음성이 장면보다 길면 멈춘다(대본을 줄이거나 장면을 늘린다). 영상을 다시 녹화했으면 이 명령을 다시 실행하면 된다
- 직접 녹음할 때는 녹음용 영상(`-prompter.mp4`)을 틀어 두고 화면 아래 대본을 따라 읽는다. 장면마다 대본보다 화면이 같거나 길게 맞춰 두었다(초당 4.6음절, 쉼표·마침표마다 0.3초 기준).
- 숫자는 소리 나는 대로: '여덟 살', '세 개', '두 반', '두 배'. 'AI'는 '에이아이'.
- 직접 녹음한 파일을 쓰면 장면 길이를 녹음에 맞춰 다시 뽑고, 소리를 합쳐 제출용 mp4를 만든다(`ffmpeg`로 영상 + 음성).
